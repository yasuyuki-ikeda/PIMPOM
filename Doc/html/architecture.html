2. システム構成

ソリューションを構成するプロジェクト、ビルド設定、起動から終了までの流れ、主要クラスの関係を示す。

ソリューションの構成

PIMPOM2022.sln には 4 つのプロジェクトと 2 つのソリューションフォルダ（Tool、Sample）が含まれる。構成は Debug|x64 と Release|x64 のみ。

プロジェクトパス種別役割
PIMPOMPIMPOM_EXE\PIMPOM_EXE.vcxprojEXE（MFC）起動用の薄い実行ファイル。ini のパスを決め、メインダイアログ CPIMPOMDlg を DoModal() するだけ。PIMPOM_Core を ProjectReference で参照
PIMPOM_CorePIMPOM_Core\PIMPOM_Core.vcxprojDLL（MFC 拡張 DLL）本体。画面・データ・API・ファイル入出力・フィルタ・通信のすべてを持つ。メインダイアログやメニューのリソースもここにある
data_transfer_splexternal_data_transfer_sample\data_transfer_spl\EXE（Sample）外部 C++ プログラムから PIMPOM へ画像を送るサンプル（8 章）
CloneUserDlgTool\CloneUserDlg\CloneUserDlg\EXE（Tool）カスタムファンクション追加ダイアログ。雛形ソリューションを複製する。PIMPOM と PIMPOM_Core に依存

ソリューション外だが同じリポジトリにあるもの:

PIMPOM 本体（EXE・Core）は Python も Boost もリンクしない。Python スクリプト機能は外部の python.exe をプロセス起動し、Python 側から Pimpom.pyd を通じて PIMPOM と通信する（8 章）。

起動シーケンス

  1. DLL ロード時（静的初期化） — グローバル変数 CPimpomAPI API のコンストラクタ（api_func.cpp）が動く。
    • 各ダイアログへのポインタを NULL に、画像メモリ数 data_number = 100。
    • 画像メモリのポインタ配列 pp_data_unit を上限 1000 個分確保して NULL で埋める（実体は使うときに確保）。
    • 描画フォント「ＭＳゴシック」高さ 11、RGB→灰色変換ゲイン {299, 587, 114}（/1000）。
    • 多重起動番号 pimpom_id を決める。タイトルに " - PIMPOM i" を含むダイアログを i=0..9 で探し、最初に空いている番号を使う。
  2. DllMain — AfxInitExtensionModule → new CDynLinkLibrary（EXE からリソースを使えるようにする）→ AfxSocketInit。
  3. CPIMPOM_EXEApp::InitInstance — ini のパスを決める（コマンドライン引数があればそれ、無ければ EXE のフォルダ + pimpom.ini）。CPIMPOMDlg::DoModal() を呼び、戻ったら終了。
  4. CPIMPOMDlg::OnInitDialog
    1. システムメニューに「バージョン情報」を追加。
    2. API.InitSettingFromProfile() で pimpom.ini を読み、画像メモリ数・表示サイズなどを決める。
    3. 表示用の CImageField を 2 つ作る（メイン画像領域、周辺拡大 60×60）。
    4. データウィンドウを表示状態で、ヒストグラム・作業領域・マークの各ウィンドウを非表示状態で作る。
    5. メッセージタブ、ボタン、ツールチップの配置、ドラッグ＆ドロップ受付、AVIFileInit。
    6. custom_func.ini を読み、カスタムファンクション DLL を「カスタムファンクション」メニューに ID 9999+i で登録。
    7. 背景処理スレッド BackGroundThread を _beginthreadex で開始（10 ms 周期でキャプチャ・動画再生・ライブ実行を処理）。
    8. pimpom.ini の [DEFAULT_IMAGE] とコマンドラインの画像ファイル（最大 30 個）を画像メモリ 0 から順に読み込み、表示。
    9. INVISIBLE 設定が 0 以外なら全ウィンドウを隠す（外部制御用）。
  5. 最初の OnMove — ウィンドウを (0,0) に置き、クライアント領域を画像表示サイズ＋操作部の大きさに合わせる。

終了

OnDestroy でタイマー停止、ビデオキャプチャ解放（CaptureDeInit）、AVIFileExit、CImageField 削除を行う。DLL 解放時に ~CPimpomAPI が各ダイアログ、カスタムファンクション、バックアップメモリ、画像メモリ、キャプチャ、ソケットを解放する。

コマンドライン引数は「ini ファイルのパス」と「起動時に読む画像ファイル」の両方に使われている。exe のアイコンに画像をドロップして起動すると、画像のパスが ini パスとして扱われる可能性がある。また背景スレッドを明示的に終了させる処理は無い。

クラス構造

状態はすべてグローバル唯一の CPimpomAPI API に集約されている。各ダイアログやカスタムファンクションは API のメンバ関数を呼んで画像メモリや他のウィンドウを操作する（カスタムファンクションは extern CPimpomAPI API で参照）。

CDataUnitDataWrapper/DataUnit.cpp、DataUnitConvert.cpp画像メモリ 1 面。データ配列、表示バッファ、表示パラメータ、マスク、マーク、作業領域、型変換

スレッドとイベント

要素内容
UI スレッドMFC のメッセージループ。メニュー、マウス・キー、外部プログラムからの WM_USER+100〜102 を処理する。
背景スレッドBackGroundThread。10 ms ごとに背景処理 ID を見て、CAPTURING(1) なら 1 フレーム取り込み（ライブ実行時は続けてバッチ実行）、MOVIE(2) なら表示ページを進めて末尾で先頭に戻す。ID にはほかに BATCH_EXC(3) が定義されている。SetBGProcID は現在 NOTHING(0) のときだけ受け付ける。
描画の連鎖API.DrawImage() がメイン画面・データウィンドウ・ヒストグラム・マーク値・複数画像表示などをまとめて更新する（3 章）。
カスタムファンクションへの通知メイン画面のマウス押下・移動・ドラッグ終了・右クリック、描画完了、バッチ実行の各イベントが CUserDlg に転送される。
