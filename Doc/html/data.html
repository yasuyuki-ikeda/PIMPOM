3. データ構造

画像メモリ（CDataUnit）を中心に、データ型、マスク、作業領域、マーク、表示パラメータ、表示までのデータの流れを示す。定数は include/global_define.h、構造体は include/global_typedef.h にある。

画像メモリ

  • CPimpomAPI が CDataUnit* の配列 pp_data_unit を持つ。配列は上限 DATA_NUMBER_MAX = 1000 個分確保され、実際に使う数 data_number は既定 DATA_NUMBER_DEFAULT = 100（pimpom.ini の [SETTING] IMG_NUM で変更）。
  • 空の画像メモリはポインタが NULL。画像を読み込む・生成するときに Format で確保する。
  • 番号は 0 始まり。API では CURRENT_IMAGE = -1 を渡すと現在選択中の画像メモリを指す。
  • バックアップメモリは全画像メモリで共通の 1 面。上書き・削除・処理の前に BackupDataUnit(n) で退避し、RecoverDataUnit（編集メニュー「画像データ復元」）で戻す。
IMG_NUM に上限チェックが無く、1000 を超える値を設定すると配列の範囲外を使う。既存仕様書の「画像メモリは既定で最大 30」は現行コードの既定値 100 と一致しない。

メモリ配置

すべての型で、画素 (x, y)・ページ p・チャネル c の要素は次の位置にある（W=幅、H=高さ、Ch=チャネル数）。チャネルはプレーン単位で並び、RGB も R 面・G 面・B 面の順に格納される。

index = x + y*W + W*H*(p*Ch + c)

型ごとのポインタ（pByteData、pFloatData、pShortData、pWordData、pLongData、pDwordData）のうち、その型で使う 1 本だけが確保され、残りは NULL。

複素数（COMPLEX）

実部・虚部（直交成分）と絶対値・偏角（極成分）の 4 面を持つ。CreateComplexPolarComponents で実部・虚部から絶対値（complex_image_power_log が真なら対数）と atan2 の偏角を作り、CreateComplexDescartesComponents で逆に戻す。

表示画像の生成

濃度変換

画像データ値を次式で 8bit の表示濃度に変換する（calc_bright）。BrightMax − BrightMin ≦ 0 のときは係数 0。マスクが有効で MASKED の画素は黒になる。

disp = clamp( 256 / (BrightMax - BrightMin) * (data - BrightMin), 0, 255 )

RGB 系の型でカラー表示のときは 24bit バッファに R・G・B 各面を同じ式で変換する。ヒストグラムと統計（calc_hist_and_stat）は処理範囲内で、マスクされておらず作業領域内にある画素を集計する。

カラーパレット

8bit 表示画像の各階調に割り当てる色。表示メニューで切り替える（RGB カラー表示中は変更しない）。

ID名称内容（i = 0〜255）
0グレースケール（ポジ）(i, i, i)
1グレースケール（ネガ）(255−i, 255−i, 255−i)
2虹色4 区間で B→G→R に変化
3虹色（0 を黒）虹色で i=0 のみ黒
4コサイン127.5·cos(2πi/255)+127.5
5青→黄（メニュー表記「黄色→青」）R=G=i、B=255−i
6緑→赤R=i、G=255−i
7ラベル0 は黒、それ以外は 6 色を i%6 で循環（ラベル番号が見分けやすい）

CImageField（表示領域）

  • 保持するのはウィンドウハンドル、表示領域のサイズと位置だけ。倍率とオフセットは CDataUnit 側にあるため、画像メモリごとに表示状態が保存される。
  • 描画は StretchDIBits（HALFTONE）。画像外の余白は RGB(190,190,190)、データが無いときは黒で塗る。
  • 倍率は 0.01〜100 に制限（API.ScaleImage）。ScaleImage は表示中心を保って倍率を変え、DrawAdjustedImage は縦横比を保って領域に内接させる。
  • 座標変換: 画像座標 = (画面座標 − 領域位置) / scale + offset − 0.5、逆は 画面座標 = (画像座標 + 0.5 − offset) × scale + 領域位置。

作業領域（CWorkArea）

処理や統計の対象範囲を表す図形の集合。1 画像あたり最大 WORKAREA_FIG_NUM = 10 図形。各図形は種類・OR/NOT・座標・編集モードを持つ。

種類（ID）パラメータ内外判定マウス編集
矩形（0）left, top, right, bottomありあり
幅つき直線（1）x1, y1, x2, y2, 幅 w4 頂点の外積で判定あり
楕円（2）中心 cx, cy、半径 rx, ry（回転なし）(dx/rx)²+(dy/ry)² ≦ 1あり
幅つき円周（3）中心 cx, cy、半径 r、幅 w円環の内側あり
円弧（4）cx, cy, r, 始点角, 終点角, 幅未実装（常に外側）なし
多角形（5）頂点数, 頂点[10]未実装（常に外側）なし

ある画素が作業領域に含まれるかは、「NOT 図形のどれかに入っていれば外。そうでなく OR 図形のどれかに入っていれば内」で決まる。作業領域は次に使われる。

  • ヒストグラム・平均・標準偏差の集計範囲
  • 処理範囲の矩形 GetRectArea()（フィルタ・2 値化・数式などは全図形の外接矩形内を処理する）
  • 作業領域外の自動マスク生成 SetMaskByWorkArea()、作業領域内の塗りつぶし、クリッピング
幅つき直線は判定条件の誤りにより、水平・垂直の線が常に外側と判定される。円弧と多角形は内外判定が未実装。

マスク

画素単位のフラグ（BYTE、1 = MASKED）。DoUseMask が真のとき、マスクされた画素は表示で黒く塗られ、ヒストグラム・統計・最小最大の計算から除外される。マスクはフリーハンド編集（マスク編集モード）、作業領域からの自動生成、数式（演算結果からマスク生成）、API・スクリプトで作られる。型変換するとクリアされる。

表示までのデータの流れ

画像が変わったら API.DrawImage() を呼ぶことが、各ウィンドウを更新させる約束事になっている（メッセージ通知は使わない）。

  1. データウィンドウの選択を切り替える（選択が変わったら動画再生を止める）。
  2. UpdateDispBuffer で表示画像・ヒストグラム・統計を作り直す。必要なら領域に合わせて倍率を調整。
  3. メイン画面の描画: スクロールバー・ボタン状態 → タイトルバー → 画像 → ルーラー線 → 作業領域 → マーク → 各カスタムファンクションの OnDrawMainImage_UserDlg。
  4. データウィンドウのサムネイル、ヒストグラム、マーク値一覧、複数画像同時表示、3D 画像一覧を更新。

タイトルバーの書式: データ名[型名 表示ページ/ページ数](幅×高さ) - PIMPOM（多重起動時は末尾に起動番号）。
