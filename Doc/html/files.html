10. ファイル形式と設定

読み書きできる画像ファイル形式、PIMPOM 独自形式の構造、設定ファイル（pimpom.ini、custom_func.ini）を示す。実装は API/file_io/ と api_func.cpp。

画像ファイル形式

SelectAndLoadImageFile が拡張子で形式を判定する。複数ファイルを選ぶと選択中の番号から順に展開する。

形式拡張子読込保存画像メモリの型備考

8bit 符号なし整数.raw○○BYTE生データ＋16 B フッタ（下記）
16bit 符号付き整数.short○○SHORT
16bit 符号なし整数.word○○WORD
32bit 符号付き整数.long○○LONG
32bit 符号なし整数.dword○○DWORD
32bit 浮動小数点.float○○FLOAT

生バイナリ形式

.raw／.short／.word／.long／.dword／.float／.comp／.xy／.xyz／.3d／.f3d は共通構造。データは平面順（ページ → チャネル → 行 → 列）。

[画像データ  sizeof(要素) × W × H × ページ数 × チャネル数]
[フッタ      long × 4 = { W, H, ページ数, チャネル数 }]   // 16 バイト

読込時、フッタから求めたサイズがファイルサイズと一致すればフッタを使い、一致しなければ幅・高さ・ページ数を尋ねる（初期値 640×480×1）。フッタの無い生データも読める。

PIMPOM アーカイブ（.pim）

画像メモリ 1 面の全状態を保存し、読み込むと保存時の状態を再現する。構造体 DATA_UNIT_INFO をそのまま書き出す。

順ブロック内容
1ヘッダ型、データ名（1024 B）、幅、高さ、ページ数、チャネル数、表示ページ・チャネル、RGB 表示フラグ、旧形式マーク（数と座標 256 個）、表示濃度最大・最小、表示倍率、表示オフセット、作業領域（図形種別・OR/NOT・座標 × 10）、作業領域使用フラグ、マスク使用フラグ
2表示画像8bit 表示バッファ（RGB 系は 24bit）
3マスクW × H バイト
4画像データ型に応じたデータ
5マーク個数のあと、1 個ごとに種別（short）と座標（FIGURE_UNION）。ヘッダのマーク数が 2000 なら新形式

メニュー「画像メモリ一括保存」は全画像メモリを images\bk%03d.pim に保存し、次回起動時に復元できる。

COMPLEX／XY／XYZ 型は 1 平面だけ保存して読込時に 2〜4 平面読むため、往復で壊れる。マスク使用フラグはヘッダを書いた後に代入されており、未初期化の値が保存される。

IFZ（.ifz）

{ long id = -2; long cam_connect; }                  // bit0-3 が接続カメラ
カメラごとに:
{ long format, sizeX, sizeY, grabX, grabY, grabW, grabH, size; }  // IFZ_HEADER
[画像データ]

format 0〜3: 8bit ベイヤー（周囲 1px の余白あり、平均補間でカラー化）、101〜104: ベイヤー（余白なし）、10／11／100: モノクロ。複数カメラは連番の画像メモリに展開する。

custom_func.ini

exe と同じフォルダに置き、1 行 1 件で登録するカスタムファンクションを書く（最大 10 行）。CloneUserDlg が Debug／Release 両方のファイルに追記する。

プロジェクト名=キャプション

（例）
MyFunc1=穴検出
MyFunc2=寸法計測

左辺 + .dll を読み込み、右辺を「カスタムファンクション」メニューに表示する。
